# Quickstart

:::info Reference version
This is the guided path: a local Ollama model, step by step, with checkpoints. The product
[quickstart](/reference/getting-started/quickstart) is the concise reference for the same stack.

## What you will build

You will run the complete OpenJCockpit stack on your own machine and sign in to the dashboard. At the end you see the landing hub with the **Business** and **Implementation** portals.

## Steps

### 1. Pull the model and keep Ollama running

```bash
ollama pull qwen3.6:27b
ollama list
```

<Checkpoint>
  <code>ollama list</code> shows <code>qwen3.6:27b</code>. Keep the Ollama
  daemon running while the stack is up.
</Checkpoint>

### 2. Clone both repositories next to each other

```bash
git clone https://github.com/OpenJCockpit/OpenJCockpit.git
git clone https://github.com/OpenJCockpit/OpenJCockpit-frontend.git
```

### 3. Configure and start the backend

```bash
cd OpenJCockpit
cp .env.example .env
# edit .env and set OPENAI_API_KEY
docker compose up --build
```

All other variables in `.env.example` are commented out and have working local defaults. Use a
throwaway key for tutorials and never commit `.env`.

<Checkpoint>
  The build finishes and the one-shot <code>local-seed</code> container exits
  successfully. It prepares Keycloak roles, local users and the LiteLLM keys,
  and it is safe to run again.
</Checkpoint>

:::caution Health is not readiness for inference
`/actuator/health` reports `UP` even when Ollama is unreachable. A missing model only shows up when
the first LLM call fails. See [Troubleshooting](troubleshooting.mdx).
:::

### 4. Start the dashboard

In a second terminal:

```bash
cd OpenJCockpit-frontend
docker compose up --build
```

The dashboard proxies `/api` to `ai-control-service` on port `9080` and signs in against Keycloak on
`8080`.

### 5. Sign in

Open `http://localhost:4000`. You are redirected to the OpenJCockpit login page. Sign in with a
seeded local user.

<LocalOnlyWarning />

The seeded users and their passwords are listed in the product
[authentication guide](/reference/getting-started/authentication).
Use `tony`, who also has the `openjcockpit-admin` role.

<Checkpoint>
  After login you land on the hub: an intro greeting with your first name, a top
  bar, and the **Business** and **Implementation** portals.
</Checkpoint>

### 6. Pull the job image once

Workflow runs on a project use a container image that is not pulled automatically:

```bash
docker pull eclipse-temurin:25-jre
```

</WrittenAndVideo>

## What just happened

Docker Compose started Keycloak (identity), PostgreSQL, the LiteLLM gateway, OPA (policy) and the Java
services. The dashboard is a separate application that talks to them over host ports. Ollama serves
the coding model for every agent. For the architecture, see the product
[overview](/reference/concepts/overview).

## Stop, restart and reset

The [runbooks](/reference/operations/runbooks) describe every service, volume and destructive command.

| Command                  | Effect                                                 |
| ------------------------ | ------------------------------------------------------ |
| `docker compose stop`    | Stops containers, keeps all state                      |
| `docker compose down`    | Removes containers, keeps named volumes                |
| `docker compose down -v` | **Destructive.** Deletes the realm, databases and keys |
